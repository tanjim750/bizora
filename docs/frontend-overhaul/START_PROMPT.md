# Start prompts (copy and paste)

The agent team is the owner's A-Team (see `AGENT_TEAM.md`). Its session hook injects `docs/CHECKPOINT.md` into the first turn of a session, and its `system-architect` skill has a "Programme mode" that runs `PLAN.md` task by task without asking questions.

Pick **one**. Type `/` in the Antigravity agent panel first and look at the list.
- `/goal` is listed: use **A** (keeps the agent working until the goal is met; the docs describe it as built for long overnight work, no iteration cap, approvals still apply).
- Only `/system-architect` is listed: use **B**.
- Neither is listed, or slash commands do nothing: use **D** (plain text, tells the agent to read the team files directly; recommended). **C** is the shorter plain version.

Before sleeping, finish the checklist in `README.md` section "Before you sleep"; an approval prompt nobody answers stops the whole night.

## 0. Two-minute smoke test (do this first, awake)
Paste this and read the answer; it costs almost nothing and tells you whether the team loaded:
```text
Do not change anything. In one short list tell me: (1) which rules, skills and subagents you can see, (2) whether you were given docs/CHECKPOINT.md at the start of this session, (3) the current git branch, (4) the first not-done task in docs/frontend-overhaul/PLAN.md.
```
Expected: the A-Team rules and skills (`system-architect`, `design-review`, `verify`, ...), the four reviewer agents (if the IDE supports them), branch `frontend-overhaul`, task `T0-1` (Preflight) or the first task not marked done in `PROGRESS.md`. If the hook did not run, it should still find the branch and task by reading the files; that is fine.

First read docs/CHECKPOINT.md, then the always-on rules in .agents/rules/, then docs/frontend-overhaul/MASTER_PROMPT.md, PLAN.md, PROGRESS.md, AUDIT_REPORT.md and DESIGN_SPEC.md. Work on the local branch frontend-overhaul. Frontend only: you may change frontend/**, docs/frontend-overhaul/** and docs/backend-issues/**; never touch the backend, never git push, never open .env files, never print secrets, never ask me questions (I am asleep: record blockers in PROGRESS.md and continue with the next independent task). Done means ALL of the following: (1) every task in docs/frontend-overhaul/PLAN.md is marked done in PROGRESS.md with its commit hash and verification evidence, or marked blocked with the reason after three honest attempts; (2) in frontend/, npm test, npm run format:check and npm run build all exit 0; (3) node docs/frontend-overhaul/scripts/verify-pages.mjs --strict --label final --theme light,dark over every page and tab of the nine workspaces at 1440x900 and 390x844 reports 0 issues, or each remaining issue is explained in PROGRESS.md; (4) docs/frontend-overhaul/FINAL_REPORT.md exists and every backend problem you found is recorded in docs/backend-issues/; (5) git status shows only the expected untracked .agents/, GEMINI.md and docs/CHECKPOINT.md, with one local commit per task on branch frontend-overhaul and nothing pushed. Follow the phases and time boxes in PLAN.md (about 7 to 8 hours); do not stop after one or two hours; update docs/CHECKPOINT.md after every task; at the end of every phase run the four reviewer agents (design-reviewer, code-reviewer, security-reviewer, architect-reviewer) in parallel with invoke_subagent or, if they are unavailable, run /design-review, /code-review, /security-review and /architect-review yourself, and fix every critical, high and medium finding.

## E. Formal theme (palette and typography), then continue the programme (added 2026-11-10)
Use this when the layout is fine but the text and colours look heavy or unclean. It installs the pre-verified formal palette and the single typeface, fixes the run-together headings, then carries on with the unfinished pages. Paste the whole block as one message.
```text
You are the autonomous lead of the Bizora frontend overhaul. I will NOT answer questions: never ask me anything, never wait for approval. When unsure, take the default from the docs, record the decision in docs/frontend-overhaul/PROGRESS.md and continue. If truly blocked, write it under "Blocked / questions for the owner" in PROGRESS.md and move to the next independent task.

Context first: read docs/CHECKPOINT.md, every file in .agents/rules/, docs/frontend-overhaul/MASTER_PROMPT.md, PLAN.md, PROGRESS.md and DESIGN_SPEC.md, and .agents/skills/system-architect/SKILL.md (last section "Programme mode"). Slash commands may not exist: open skills as files (.agents/skills/<name>/SKILL.md) and reviewers as files (.agents/agents/<name>.md). Branch must be frontend-overhaul. The earlier run stopped after T4-3 (Phase 4 is done, Phase 5 pages are not). Check the servers with `bash docs/frontend-overhaul/scripts/dev-status.sh` (start them per .agents/skills/start-servers/SKILL.md if DOWN).

FIRST do task T1-6 "Formal theme: palette and typography" (it is in PLAN.md). The owner saw the running app: layout is good, but text and colours look heavy and unclean (headings with negative letter-spacing run words together, e.g. "Opencases" and "requireshuman review"; three typefaces; weight 700 everywhere; vivid default-blue outline buttons and links; navy-blue dark mode; monospace for ordinary dates). The palette and typeface are already chosen and contrast-verified (48 pairs per theme, 0 failures). Do NOT choose or change any colour value yourself; read docs/frontend-overhaul/assets/PALETTE_FORMAL.md and use docs/frontend-overhaul/assets/tokens.formal.css exactly.
1. Install: copy assets/tokens.formal.css over frontend/src/styles/tokens.css and over docs/frontend-overhaul/assets/tokens.css; run `cd frontend && npx prettier --write src/styles/tokens.css`. No token name was removed, so nothing else breaks.
2. Fonts in frontend/src/app/layout.js: remove Plus_Jakarta_Sans, Inter and JetBrains_Mono. Add IBM_Plex_Sans from next/font/google (subsets ['latin'], weights ['400','500','600'], variable '--font-plex', display 'swap') and IBM_Plex_Mono (['400','500'], variable '--font-plex-mono'); keep Noto_Sans_Bengali (variable '--font-bengali'); update the html className. 3. CSS cleanup in frontend/src/styles/*.css (use tokens only, no raw values):

   b. Headings: font-weight var(--weight-heading) (600), line-height var(--leading-heading). Replace every font-weight 700 or 800 (about 13 places) with var(--weight-heading) for titles and KPI values, or var(--weight-medium) for labels, buttons and table headers. Only 400, 500 and 600 may remain.

Audit all 9 uses of --font-mono.
   d. Text hierarchy: page descriptions, card subtitles and KPI labels use var(--color-text-secondary); var(--color-text-muted) only for hints, metadata, timestamps and placeholders. Page title 26, card title 16, section title 18, body 14, table 13 (tokens already set).
   e. Buttons: only the single main action of a view is a solid primary button. Secondary, ghost, small-secondary and "View proposals"-style buttons are neutral: surface background, 1px var(--color-border-input), var(--color-text) text, hover var(--color-surface-subtle). Danger stays solid danger. Links stay var(--color-primary), underline on hover. No blue outlines on neutral actions.
   f. Cards and tables: surface background, 1px var(--color-border), radius var(--radius-md), no shadow in light mode (overlays keep theirs); table header row on var(--color-surface-subtle) with 12px weight 500 secondary text; row dividers var(--color-border); cell padding about 10px 16px. Banners and chips keep their semantic tokens and nothing louder.

4. Update docs/frontend-overhaul/DESIGN_SPEC.md and .agents/rules/20-design-system.md where they name Plus Jakarta Sans, Inter or JetBrains Mono, or the old hex values, so the docs say IBM Plex Sans plus the formal tokens.
```

## If it stops
Say: `/system-architect continue` (or paste prompt C again). A new session gets `docs/CHECKPOINT.md` from the hook (or reads it, as prompt C says) and carries on after the last finished task. Check `git log --oneline -5` and `PROGRESS.md` to see how far it got.
