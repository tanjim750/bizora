## 2. Required behaviour
1. `frontend/src/lib/checkout/validation.ts`:
   - `type CheckoutFormValues = { email: string; phone: string; firstName: string; lastName: string; line1: string; line2: string; city: string; postalCode: string; countryCode: string; shippingMethodId: string; paymentMethodId: string; note: string }` and `emptyCheckoutValues(store: StoreConfig, email = ''): CheckoutFormValues` (countryCode = first country, shippingMethodId = first method id, paymentMethodId = first enabled method id or `''`).
   - `CHECKOUT_FIELDS` = the ordered list of keys above (used for the error summary order).
   - `validateCheckout(values, store): { ok: true; body: Omit<PlaceOrderBody, 'expectedTotal'> } | { ok: false; errors: Partial<Record<keyof CheckoutFormValues, string>> }` — trims strings; empty `line2` → `null`; empty `note` → `null`; messages exactly: email empty "Enter your email address." / invalid "Enter a valid email address."; phone empty or not `^\+?[0-9 ()-]{7,20}$` "Enter a phone number we can call."; firstName "Enter your first name."; lastName "Enter your last name."; line1 < 3 chars "Enter your street address."; city < 2 "Enter your city."; postalCode not `^[A-Za-z0-9 -]{3,10}$` "Enter a valid postal code."; countryCode not in `store.countries` "Choose a country."; shippingMethodId not in `store.shippingMethods` "Choose a delivery method."; paymentMethodId not an enabled method "Choose a payment method."; note > 500 "Keep the note under 500 characters."; line2 > 120 "Keep this under 120 characters.".
   - `validateField(name, values, store): string | undefined` — the message for one field (used on blur).
   - `toPlaceOrderBody(body, expectedTotal: Money): PlaceOrderBody`.
   - `mapApiFieldErrors(fields: Record<string, string[]> | null): Partial<Record<keyof CheckoutFormValues, string>>` — maps API paths to form keys: `email`, `phone`, `shippingAddress.firstName` → `firstName`, `shippingAddress.lastName`, `shippingAddress.line1`, `shippingAddress.line2`, `shippingAddress.city`, `shippingAddress.postalCode`, `shippingAddress.countryCode` → `countryCode`, `shippingMethodId`, `paymentMethodId`, `note`; first message of each; unknown paths ignored.
2. `frontend/src/lib/checkout/idempotency.ts`: `newIdempotencyKey(): string` → `crypto.randomUUID()`; `createAttemptKeys()` returning `{ current(): string; renew(): string }` — `current` returns the same key until `renew` is called (the page renews after a 4xx it can fix, or after `IDEMPOTENCY_CONFLICT`; it reuses the key after a network error).
