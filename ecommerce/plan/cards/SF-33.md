## 2. Required behaviour
`frontend/tests/e2e/journeys.spec.ts`, projects `desktop-light` and `mobile` only (skip others):
1. **Guest checkout:** `/shop` → click the product link "Field Notebook" → choose radio "Ink" → click "Add to cart — ৳950" → dialog "Your cart (1)" visible → click "Checkout" → fill Email `guest@example.com`, Phone `01712345678`, First name `Rafi`, Last name `Karim`, Address `House 1, Road 2`, City `Dhaka`, Postal code `1209` → the submit button text matches `/^Place order — ৳1,081\.50$/` (950 + 80 delivery = 1,030; VAT 5 % = 51.50) → click it → URL matches `/\/order-confirmation\/AUR-\d{6}\?token=/` → heading "Thank you, Rafi!" and text "A confirmation will be sent to guest@example.com." → go to `/cart` → "Your cart is empty.".
2. **Validation:** on `/checkout` with one item, submit empty → alert "Please fix these fields:"; click the link "Enter your email address." → the email input is focused.
3. **Sign-in merges the cart:** add "Market Tote" (Oat) as guest → `/account/sign-in` → `demo@aurelo.test` / `demo-pass-123` → lands on `/account` with heading "Hello, Nadia" → the header button "Cart, n items" has n ≥ 1 → open the cart → line "Market Tote" present.
4. **Account history:** signed in as demo → `/account` lists "AUR-100142" → click it → heading "Order AUR-100142" → "All orders" back.
5. **Wrong password:** `/account/sign-in` with `nobody@example.com` / `wrong-password` → alert "That email and password don't match." (use a unique email per run so the rate limit is never hit: `nobody+${Date.now()}@example.com`).
6. **Sold out:** `/products/ember-teapot` → button "Sold out" disabled.

Locators: use `getByLabel('Email', { exact: true })`, `getByLabel('Password', { exact: true })` and role queries scoped to `page.getByRole('main')` (the footer has its own "Email address" field; the password toggle is named "Show password").
