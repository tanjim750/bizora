## 1. Context
The mock backend is a plain TypeScript module (no Next.js imports) that answers `MockRequest`s exactly like the real backend will. It is used in-process by server code (SF-09) and through a route handler by the browser (SF-08). Print the exports of `frontend/src/lib/api/schemas.ts` and `types.ts` first.

## 2. Required behaviour
1. `frontend/src/mocks/server/http.ts`:
   - Types `MockRequest = { method: 'GET' | 'POST' | 'PATCH' | 'DELETE'; path: string; query?: Record<string, string | string[] | undefined>; body?: unknown; headers?: Record<string, string>; cookies: Record<string, string> }` and `MockResponse = { status: number; body: unknown; headers: Record<string, string>; setCookies: string[] }`.
   - `json(status, body, setCookies = [])` → MockResponse with `headers: { 'content-type': 'application/json', 'x-request-id': <id> }`; `noContent(setCookies = [])` (status 204, body `null`); `apiError(status, code, message, fields = null, details = null)` → the §3 envelope with `requestId` equal to the header; `newRequestId()` → `'req_' + 8 random hex chars`.
   - `zodFields(error: z.ZodError)` → `Record<string, string[]>` keyed by `issue.path.join('.')`.
   - `queryOne(query, key)` (first value as string or undefined) and `queryAll(query, key)` (array of strings).
   - `cookie(name, value, maxAgeSeconds)` → `` `${name}=${value}; Path=/; HttpOnly; SameSite=Lax; Max-Age=${maxAgeSeconds}` `` and `clearCookie(name)` (Max-Age=0). Cookie names exported as `CART_COOKIE = 'aur_cart'`, `SESSION_COOKIE = 'aur_session'`.
2. `frontend/src/mocks/server/db.ts`:
   - Type `MockDb = { store; home; categories; products: Product[]; users: MockUser[]; carts: Map<string, MockCart>; sessions: Map<string, string /* customerId */>; orders: MockOrder[]; idempotency: Map<string, { bodyHash: string; response: MockResponse }>; signInFailures: Map<string, number[]>; newsletter: Set<string>; nextOrderSeq: number }` with `MockCart = { id: string; customerId: string | null; lines: { id: string; variantId: string; quantity: number }[]; updatedAt: string }`, `MockUser = Customer & { password: string }`, `MockOrder = Order & { customerId: string | null; confirmationToken: string }`.
   - `getDb()`: returns `globalThis.__aureloMockDb`, creating it on first use from a deep copy (`structuredClone`) of the six fixtures with `nextOrderSeq: 200`. `resetMockDb()` deletes and recreates it.
   - `recomputeStock(product)`: recalculates every variant's `stockStatus` from `availableQuantity` and the product's aggregate `stockStatus` and `defaultVariantId` (03-API-CONTRACT §4.6, 04-FIXTURES §3.1).
   - `findVariant(variantId)` → `{ product, variant } | null`.
3. `frontend/src/mocks/server/catalog.ts` — handlers returning `MockResponse`:
   - `getStore()` → 200 `StoreConfig`; `getHomeContent()` → 200 `HomeContent`; `listCategories()` → 200 `{ items }` with `productCount` computed from current products.
   - `listProducts(query)`: validate params (§5.2 table; invalid → 400 `VALIDATION_FAILED` with `fields` e.g. `{ "pageSize": ["Must be between 1 and 48."] }`, `{ "sort": ["Unknown sort."] }`, `{ "minPrice": ["Must be a whole number ≥ 0."] }`); filter (q, category, collection, color, size, price, inStock); facets computed per §4.10 (each facet's counts ignore that facet's own filter; price range ignores the price filter; empty → `price: null`); sort (featured = fixture order, ties by name; newest = `createdAt` desc; price asc/desc by `price.amount` then name; name-asc with `a.name.localeCompare(b.name, 'en')`); paginate; respond `{ items: ProductSummary[], page, pageSize, totalItems, totalPages, facets }`. `export function toSummary(product)` builds the §4.8 object (first two images); it is exported because later tests reuse it.
   - `getProduct(slug)` → 200 `Product` or 404 `NOT_FOUND` ("Product not found."). `getRelated(slug, limit)` per §5.2 rule (same category first in fixture order, then others in fixture order, out-of-stock last, never itself, limit 1–12 default 4; invalid limit → 400). `suggest(q)` per §5.2 (trimmed, < 2 chars → empty arrays; products matching name/subtitle case-insensitively, max 5, `image` = first image; categories whose name contains q, max 3).
   - `subscribeNewsletter(body)`: validate `{ email }` with `z.email()` (zod 4) — invalid → 400 with `fields.email = ['Enter a valid email address.']`; add lower-cased email to `db.newsletter`; 202 `{ status: 'subscribed' }`.
4. `frontend/src/mocks/server/router.ts`: `export async function handleMockRequest(req: MockRequest): Promise<MockResponse>`:
   - Normalise: strip a trailing `/`; lower-case header names.
   - 415 rule: if `req.body !== undefined` and the `content-type` header does not start with `application/json` → 415 `UNSUPPORTED_MEDIA_TYPE`.
   - Route table (exact method + path, `:param` segments): `GET /store`, `GET /content/home`, `POST /newsletter`, `GET /categories`, `GET /products`, `GET /products/:slug`, `GET /products/:slug/related`, `GET /search/suggest`. All other method/path pairs → 404 `NOT_FOUND` ("Route not found."). (SF-08 adds the cart, auth, checkout and orders routes to this table.)
   - Any thrown error inside a handler → 500 `INTERNAL` ("Unexpected error.").

## 3. Tests (write first) — `frontend/tests/unit/sf-07-mock-catalog.test.ts`
`beforeEach(() => resetMockDb())`. Helper `call(method, path, query?)` → `handleMockRequest({ method, path, query, cookies: {} })`. Every 2xx body is parsed with the matching schema from `@/lib/api/schemas` (this proves the mock follows the contract). Assertions:
- `GET /store` 200 + `StoreConfigSchema`; `GET /content/home` 200 + `HomeContentSchema`; `GET /categories` 5 items, ceramics `productCount` 5.
- `GET /products` → `ProductListSchema`; `totalItems` 24, `pageSize` 24, `totalPages` 1, first item slug `ondo-stoneware-mug`; response header `x-request-id` starts with `req_`.
- `collection=sale` → 5; `collection=new` → 5; `collection=featured` → 10; `category=bags` → 5; `q=MUG` → contains `ondo-stoneware-mug`; `color=['Sand','Ink']` → every item has a Sand or Ink swatch; `size=King` → 1 item (`still-bed-linen`); `minPrice=100000&maxPrice=200000` → every price within range; `inStock=true` → 23 items.
- facets: with `category=ceramics`, `facets.categories` still lists all 5 categories (own facet ignored); `facets.colors` counts only ceramics products.
- sort `price-asc` first item price 95000; `price-desc` first `dusk-floor-lamp`; `newest` first `commute-backpack`; `name-asc` first `arc-table-lamp`.
- `pageSize=5&page=5` → `items.length` 4, `totalPages` 5; `page=99` → 200 with `items: []`; `pageSize=100` → 400 `VALIDATION_FAILED` with `fields.pageSize`.
- `GET /products/ondo-stoneware-mug` → `ProductSchema`, 3 variants; `GET /products/nope` → 404, body parses with `ErrorEnvelopeSchema`, code `NOT_FOUND`.
- `GET /products/ondo-stoneware-mug/related` → exactly `['kiln-serving-bowl', 'tide-dinner-plates', 'hollow-bud-vase', 'drift-linen-throw']` (same category in fixture order, then others; the sold-out `ember-teapot` goes last and falls outside the limit).
- `GET /search/suggest?q=m` → both arrays empty; `q=lamp` → products include `arc-table-lamp`, ≤ 5.
- `POST /newsletter` with `{ email: 'x' }` and header `content-type: application/json` → 400 with `fields.email`; valid email → 202 `{ status: 'subscribed' }`; same request with header `content-type: text/plain` → 415.
- `GET /nothing` → 404 `NOT_FOUND`.
