## 1. Context
`npm run contract:check` already exists in `package.json` (SF-01) and points at `vitest.contract.config.ts`, which does not exist yet. The check must work against: (a) the mock, in-process, when `CONTRACT_BASE_URL` is not set; (b) a real backend over HTTP when `CONTRACT_BASE_URL=https://api.example.com/v1` is set. It uses `createApi` and the schemas, so every response is validated by the same zod schemas the app uses.

## 2. Required behaviour
1. `frontend/vitest.contract.config.ts`: same as `vitest.config.ts` but `test.include: ['tests/contract/**/*.test.ts']`, `environment: 'node'`, `testTimeout: 20000`, `setupFiles: []`.
2. `frontend/tests/contract/live-contract.test.ts`:
   - Transport: if `process.env.CONTRACT_BASE_URL` → a cookie-jar wrapper around `createHttpTransport(base)` (stores `set-cookie` from responses — read via `res.headers.getSetCookie()` inside a custom fetch passed to the transport, or implement a tiny local transport in the test file that does the same as `transport-http` plus cookies; keep it in the test file); else `mockTransport` with `resetMockDb()` in `beforeAll` and a cookie jar implemented by calling `handleMockRequest` directly (a local transport in the test file that passes `cookies` and applies `setCookies`).
   - Print at start: `Checking contract against: <base or "built-in mock">`.
   - Read-only checks (always): `store.get()`; `content.home()`; `catalog.listCategories()` non-empty; `catalog.listProducts()` and `listProducts({ sort: 'price-asc', pageSize: 5 })` (prices ascending); `listProducts({ pageSize: 0 })` rejects with `VALIDATION_FAILED` (call through the transport with raw query `pageSize=0`); take the first product slug → `catalog.getProduct(slug)` and `getRelated(slug)`; `getProduct('this-slug-does-not-exist-123')` rejects `NOT_FOUND` with status 404; `catalog.suggest('a')` returns empty arrays.
   - Error envelope: an unknown route `GET /this-route-does-not-exist` returns a body that parses with `ErrorEnvelopeSchema` and an `x-request-id` header.
   - Write checks (skipped when `CONTRACT_READONLY=1`): `cart.get()` (empty cart shape); add the first in-stock variant of the first product with quantity 1 → `itemCount` ≥ 1; `updateLine` to 2; `removeLine`; register a unique user `contract+<timestamp>@example.com` / `contract-pass-123` → 201 then `auth.me()`; add an item; `checkout.quote(<first shipping method id>)`; `placeOrder` with the quote total and a UUID key → 201; repeat the same call with the same key → same order number; `orders.get(number)` → 200; `orders.list()` contains it; `auth.signOut()` → then `auth.me()` rejects 401.
   - Each check is its own `it(...)` with a clear name, e.g. `it('GET /products returns Paginated<ProductSummary> with facets')`, so a backend developer sees exactly which endpoint is wrong.
3. `frontend/README.md`: add a section "Checking a backend against the contract" with:
   ```bash
   npm run contract:check                                              # the built-in mock
   CONTRACT_BASE_URL=https://api.example.com/v1 npm run contract:check  # a real backend (creates a test user and an order)
   CONTRACT_READONLY=1 CONTRACT_BASE_URL=https://api.example.com/v1 npm run contract:check  # read-only
   ```
   and one line: "When it is green, set `API_BASE_URL` in `.env.local` to the same base URL and restart."
