## 2. Required behaviour
1. `frontend/src/lib/auth/redirect.ts`: `safeNextPath(next: string | null | undefined, fallback = '/account'): string` — returns `next` only if it starts with `/`, does not start with `//` or `/\`, contains no `:` before the first `/` segment, has no control characters and is at most 200 chars; else `fallback`. Also never returns a path starting with `/account/sign-in` or `/account/register` (→ fallback).
2. `frontend/src/lib/auth/validation.ts` (zod): `validateSignIn(values: { email: string; password: string })` and `validateRegister(values: { firstName; lastName; email; password })` → `{ ok: true; data } | { ok: false; errors: Record<string, string> }` with the exact messages: email empty "Enter your email address.", invalid "Enter a valid email address."; password empty "Enter your password."; register password < 8 "Use at least 8 characters.", > 128 "Use at most 128 characters."; first name empty "Enter your first name."; last name empty "Enter your last name."; names > 60 "Keep this under 60 characters.". Emails are trimmed; passwords are not.
3. `frontend/src/components/account/AuthForm.tsx` (`'use client'`): props `{ mode: 'sign-in' | 'register' }` (this card implements and tests `sign-in`; `register` fields are built now too but its page comes in SF-25). Centered card `mx-auto max-w-md py-16`; `h1` "Sign in" / "Create your account"; sub-line "Welcome back." / "Track orders and check out faster."; `form noValidate`; field ids `${mode}-<field>` (e.g. `sign-in-email`, `sign-in-password`, `register-first-name`); fields per 05-PAGES §8 with the `autocomplete` values there; password field has a toggle `IconButton` `aria-label` "Show password"/"Hide password", `aria-pressed`. On submit: validate; with errors, set them on the fields (`aria-invalid`, messages) and focus the first invalid input. Else call `useSessionStore.getState().signIn(data)` (or `register(data)`) with Button `loading`. Errors: `INVALID_CREDENTIALS` → form `<p role="alert">` "That email and password don't match."; `RATE_LIMITED` → `toUserMessage(e)`; `EMAIL_TAKEN` → email field error "An account with this email already exists." plus a `Link` "Sign in instead" (`/account/sign-in` keeping `next`); `VALIDATION_FAILED` → `fields` mapped onto the inputs; others → `toUserMessage(e)` in the form alert. Success → `router.replace(safeNextPath(searchParams.get('next')))`.
   Footer link: sign-in → "New here? Create an account" → `/account/register` (+ `?next=` when present); register → "Already have an account? Sign in".
   Already signed in: keep a `submittedRef` (true once a submit starts); in an effect on session `status`, when `status === 'signed-in'` and `submittedRef.current === false` → `router.replace('/account')` (this covers arriving while signed in, without racing the post-submit redirect).
4. `frontend/src/app/(store)/account/sign-in/page.tsx`: `export const metadata = { title: 'Sign in' }`; renders `<Suspense><AuthForm mode="sign-in" /></Suspense>` (useSearchParams needs Suspense).
